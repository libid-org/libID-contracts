# libid-identity

The off-chain half of the libid identity keys: handle normalization, the id
rules and, with the `node` feature, the nodes a binding is stored under.

`normalize(raw, rules)` turns a platform handle into the one form the identity
system hashes into a node, mirroring the circuits' `lib/identity` and
`contracts/handles/HandleNormalizer.sol` byte for byte: a closed ASCII byte
transform that folds `A-Z` to `a-z` and changes nothing else. It refuses
rather than repairs: no byte is trimmed and no `@` is stripped, so
`" @Alice_1 "` is an error, not `alice_1`. It is deliberately not Unicode
case folding and not UTS-46.

```rust
use libid_identity::{normalize, HandleError, Rules};

assert_eq!(normalize("Alice_1", Rules::X), Ok("alice_1".to_string()));
assert_eq!(normalize(" @Alice_1 ", Rules::X), Err(HandleError::BadCharacter));
```

`check_id(id, rules)` accepts an id exactly as the platform sent it, or says
why no circuit would hash it. Ids are never normalized.

With the `node` feature, `handle_node(platform_key, raw)` and
`id_node(platform_key, id)` compute `SHA256(tag || value)`, the node the
platform's circuit outputs and `IdentityRegistry` and `HandleEscrow` key by.
Both answer `None` for a platform key the table does not know:

```toml
libid-identity = { version = "0.17", features = ["node"] }
```

```rust
// hashlib.sha256(b"libid.github.handleoctocat"): what HandleEscrow.deposit takes.
let node = libid_identity::handle_node("github", "OctoCat").unwrap().unwrap();
assert_eq!(node[..4], [0x38, 0x1f, 0xb9, 0xd7]);
// hashlib.sha256(b"libid.github.user-id583231"): what resolveId takes.
let id = libid_identity::id_node("github", "583231").unwrap().unwrap();
assert_eq!(id[..4], [0x47, 0x59, 0x02, 0xb2]);
assert!(libid_identity::handle_node("myspace", "tom").is_none());
```

The per-platform rules (`Rules::X`, `Rules::GITHUB`, `Rules::GOOGLE`), the
node tags and the shared vector table come from
`contracts/handles/handles.json`, generated by
`scripts/regen-identity-handles.py`. Solidity, Rust, TypeScript and Noir each
run the same table, so a normalizer that drifted from the chain fails a test
instead of looking up a node the chain never wrote.

`handle_vectors` also carries each platform key (`PLATFORM_X_KEY`, …), and
`rules_for` returns a platform's rules by its key; `keccak256` of the key is
the platform id the contracts take.

## Dependencies

None by default, on purpose: every consumer of the identity system needs the
transform, and none of them should inherit anything for it. The `node`
feature adds `sha2`, for the hash, and nothing else.
